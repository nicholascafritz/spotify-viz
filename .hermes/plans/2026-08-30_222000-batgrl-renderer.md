# Batgrl Renderer Migration Plan

> **For Hermes:** Execute this plan with TDD; preserve the CAVA/MPRIS bridges and move only scene composition, frame presentation, input, and resize ownership to batgrl.

**Goal:** Replace the sparse ANSI cathedral with a dense, layered, truecolor batgrl scene that remains pure ASCII, follows CAVA bands, and keeps ncspot control scoped through MPRIS.

**Architecture:** Keep `cava.py`, `mpris.py`, `signal.py`, and `config.py` as source adapters. Add a testable pure layer compositor that produces fixed-size ASCII cell layers for architecture, void, fog/particles, transient tears, and status. A small batgrl `App` maps those layers to persistent `Text` gadgets and runs the nonblocking app loop with batgrl resize/key events.

**Tech stack:** Python 3.13, batgrl 0.51, numpy (transitive), CAVA raw stream, playerctl MPRIS, pytest.

### Task 5: Polish, document, and validate live behavior

**Files:** Modify `README.md`, relevant tests

2. Run `uv run pytest -v`, `uv build`, and a live Kitty/PipeWire/ncspot run.
3. Capture and inspect a full-height terminal frame for dense foreground/midground/background separation, readable off-centre void, audio response, resize behavior, and terminal restoration.
4. Perform an independent code review, merge the feature branch into main without touching the user-authored design spec, then push only reviewed commits.

**Risks and decisions:** batgrl is intentionally accepted as a heavier dependency because it supplies truecolor canvas cells, persistent layers, key events, resize lifecycle, and an async event loop. `asciimatics` was rejected because its documented color model is 256-color; Textual was rejected because it is a dashboard framework; notcurses was rejected because it requires a C-first integration. The pure ASCII constraint remains: batgrl receives only ASCII glyphs, not images or Unicode art.
